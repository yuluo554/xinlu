## M6 · 发布（顺序不可颠倒）

```
npm run build → dist 干净环境验证（本地静态服务实玩冒烟）
→ Pages 部署 → 实开 URL 可玩
→ CHANGELOG.md（含数据口径版本）→ plan/05 主体（tag 之前落盘）
→ tag（v1.0.0）→ GitHub Release（五部分说明 + 附 dist.zip + sha256）
→ plan/05 追加「tag 后事实」分栏（部署 URL、附件 sha256、Traffic 基线）
```

**出口门（发布完成 = 全部满足）**：三件套齐；Release 五部分（变更摘要 / 口径版本 / 是否需重开历史存档 / 校验和 / 已知问题）；tag 晚于构建与验证；plan/05 两分栏齐备。
**评审门**：发布前对照 00 §实物表与 01 §四验收标准逐行打勾，缺一不发版。

## 风险与恢复

| 风险 | 对策 |
|---|---|
| 本机直连 GitHub 不通（已实测） | 克隆/拉取走 gh-proxy 镜像（已验证可用）；push 依次尝试：镜像 push 地址 → SSH:22 → 失败则本地提交齐全，发布动作顺延到网络可用时（plan/05 留痕，不虚报发布） |
| 完整人生内容量拖期 | 密度口径是底线而非上限；validate 允许阶段性绿（先低密度后补齐），M4 出口必须达标；DoD 不降级，要降必须回 00 决策记录留行 |
| 存档 schema 后期破坏性调整 | v 字段 + 迁移函数在 M2 就位；破坏性改动 → v+1 + 迁移测试 |
| 事件引用死锁（pre 指向不可能状态） | validate 静态查 + dogfooding 实玩双重防线 |
| MBTI 口径争议 | 01 §十已知限制公开声明；锚点查证 M1 前完成三态 |
