## 风险与恢复

| 风险 | 对策 |
|---|---|
| D1 不拍板导致 v2 停摆 | 前置项有时限：v2-M1' 可先做（1.1/1.3 不依赖素材）；2.x 开工前必须拍板，逾期升级为阻塞项（⛔） |
| 美术接入破坏 v1 冻结契约 | K11 纪律：新增文件 + 新增导出；E2E 与 v1 测试基线双保险 |
| 大文件经镜像截断（实测先例） | 下载一律校验魔数/尺寸（PNG IEND / GIF 头 / WebP VP8 头），必要时 `curl -C -` 续传 |
| dist 超预算 | 压缩 WebP > 减帧 > 降分辨率顺序裁剪；预算门红灯即停发 |
| B1 改判定引发连锁 | 双层版本规则（v2.0.0 主版本 + 重开声明）；可达性扫描 + 防回退测试双防线 |
| 多会话/多工具协作冲突 | 开工前 `git status` 惯例（沿 sprint 公共规则）：工作区有他人未提交改动先问 |
