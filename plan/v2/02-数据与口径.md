# 02 · 《心路》v2.0 数据与口径（单一定义源）

> 本档是 v2 新增数值/映射/规格口径的**唯一事实源**（K1 纪律延续：引擎/前端/测试/数据文件不得复写第二份表述；v1 口径仍以 [../02-数据与口径.md](../02-数据与口径.md)（v1 套件）为单源，本档只做增量）。

## 一、人格鱼 avatar 参数口径

**纯函数契约（签名随本档冻结）**：`createFishParams(dims: Dims): FishParams`——输入终局前实时四维值，输出表现参数；同输入恒同输出（无随机）。

| 参数 | 驱动维度 | 口径（唯一表） |
|---|---|---|
| `activity` 活跃度 | `ei` | ei=0 → 0，ei=100 → 1，线性映射；idle 动画播放间隔 = `1600 - activity*1000` ms（即 I 沉底 1.6s/帧，E 巡游 0.6s/帧）；位移幅度 = `4 + activity*12` px |
| `mood` 表情倾向 | `tf` | tf 值域三段：<40 偏「思」系表情、40–60 中性、>60 偏「暖」系表情；具体帧位由 02 §二映射表锁定 |
| `ambience` 氛围层 | `sn` | sn<50 → 氛围层显示、饱和度 `0.7+sn/100`；sn≥50 → 隐藏氛围层（S 清淡写实、N 幻彩由饱和度与鱼群密度两个变量承载：鱼群数量 = `round(2 + (100-sn)/25)`，即 N 侧最多 6 群、S 侧 2 群） |
| `orderliness` 排布感 | `jp` | 报告卡/图鉴布局圆角 = `20 - jp*0.12` px、栅格间距 = `8 + jp*0.16` px（J 更规整、P 更松散）；仅用于 v2 新增界面，不改 v1 已有布局 |

- 全部参数经钳制后使用；任何 NaN/越界 → 回落中位值 50 的参数集（沿用 viz `sanitize` 纪律）；
- 16 型 = 四维区间组合的**派生结果**，不为型号新增素材或硬编码分支（K：`fish.ts` 中不得出现 16 型字面量分支）。

## 二、表情映射口径（19 张，覆盖 100%）

`src/data/fish-mood-map.json` 唯一存放；`fish/` 目录 19 张编号表情（01–26 命名）→ 三类触发：

| 触发类别 | 口径 |
|---|---|
| `choice` 事件反馈 | 每张表情标注 tf 权重区间与 delta 方向（正偏移/负偏移/中性），选项点击后按 `mood` + delta 方向从候选集抽取，同种子可复现 |
| `stage` 阶段转场 | 每阶段固定 1–2 张（8 阶段 × 情绪弧），映射表锁定 |
| `ending` 终局 | 按结局类型（8 条件 + 兜底）各锁 1 张，9 个结局全覆盖 |

校验：`validate` 扩展一项——映射表覆盖 19/19、类别枚举合法、终局 9 张不重复（作为 K12 数据门新增项）。

## 三、图鉴存储口径（独立 key，不动存档 v1）

```jsonc
// localStorage key: xinlu.gallery.v2
{
  "v": 2,
  "types": { "INTJ": { "count": 3, "firstSeenAt": 1730000000000 } },  // 16 型封闭
  "endings": { "end-01": 2 },                                        // 8 条件 + 兜底
  "runs": 12                                                          // 累计通关数
}
```

- 独立于 `xinlu.save.v1`（K6 不动）；损坏 → 视为空图鉴重建，**不提示不清档**（图鉴无用户可损失内容，与存档的「绝不静默清档」语义不同——此处是刻意放宽，理由记录在案）；
- 校验：16 型键封闭、endings 键 ⊆ 结局枚举；`gallery.test.ts` 守护。

## 四、分享卡规格口径

- 画布 1080×1440（3:4 竖版）；必含元素：人格鱼主视觉、终局雷达、MBTI 型号字母、画像一句话（portraits.json 复用）、关键抉择 3 条、水印（`watermark.webp` 进水印池左下角，尺寸 ≤ 120px）；
- 导出文件名：`xinlu-<mbti>-<yyyymmdd>.png`；纯客户端 Canvas 生成，零上传；
- 导出函数纯逻辑（布局计算）与绘制分离，前者可单测（canvas stub 只测计算结果，不测像素）。

## 五、B1 可达性口径（沿 v1 密度矩阵增量）

- 新增事件全部守 v1 schema 与偏移口径（`|Δ|` 常规 ≤3 / critical ≤8、pre 先立后引 K10）；
- 可达性判定口径：引擎级扫描——枚举每阶段选项组合的策略空间（v1 扫描 96 组的同一脚本口径），目标 = 8 条件结局 + 兜底**全可达**；
- 新增扫描脚本 `scripts/check-ending-reachability.mjs` 退出码：0 全可达 / 1 存在不可达；防回退测试 = 删掉补齐事件扫描必须报 1。

## 六、素材许可白名单（单源：[assets/README.md](../../assets/README.md) 台账；此处只引用结构）

| 层级 | 素材 | dist/git 处置 |
|---|---|---|
| ✅ 白名单 | cc-by 两组（Open Ocean / Simple Worlds）、`upstream/dafeiyu-pet/` sprites（MIT）、codex whale 系处理件（署名许可） | 可入库，credits 必署名 |
| ⚠️ 声明后可用 | `fish/` 62 张处理版（D1 拍板为 B 档时） | 可入库 + README 已知限制声明 + credits |
| ❌ 禁止 | 梗图原图（你这吃白饭的蓝色大肥鱼.png）、4 张 GIF 原件（上游无 LICENSE） | 不进 git、不进 dist、不进 Release |

`tools/check-assets-license.mjs` 判据：git 跟踪文件与 dist 内容中，图像素材路径 ⊆ 白名单清单（清单随 D1 拍板版本化）；credits 文件存在且含必需署名行（3 行，见 assets/README.md §署名文案）；任一不满足 → FAIL。

## 七、体积预算口径

- dist 构建产物 **gzip 总量 ≤ 500KB**（v1 基线 33KB，余量约 15 倍）；单张 WebP ≤ 50KB（源文件超限先压缩再入库）；
- `tools/check-dist-budget.mjs` 判据：对 `dist/` 全部产物 gzip 求和 > 500KB → FAIL；图像资产单张 > 50KB → WARN+清单（源在 assets/ 不入 dist 的不计）；
- 两门禁各配一组变异验证（改坏白名单/塞超限文件必须红），留痕后复原。

## 八、环境与兼容口径

- E2E：IAB 套路沿用 HANDOFF-M7 §五（同步 evaluate 连点、暖帧丢弃、`animation:none` 录制纪律）；脚本入口 `npm run e2e`（K7 命名惯例延续）；

- 老存档：v2 全部表现层，不读写 `xinlu.save.v1` 新字段；图鉴独立 key（§三）。
