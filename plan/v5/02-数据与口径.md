# 02 · 《心路》v5.0 数据与口径（单一定义源）

> v5 新增口径**唯一事实源**（K1 延续）；v1/v2/v3/v4 口径继续生效，本档只做增量。实现与文案不得复写第二份表述。

## 一、家庭槽位口径（缺陷修复）

**槽位枚举（封闭）与身份**：

| slot | role 显示 | 所属环 | 出现条件 |
|---|---|---|---|
| `parent-father` | 父亲 | 内环 | 非单亲-母 |
| `parent-mother` | 母亲 | 内环 | 非单亲-父 |
| `gp-paternal-grandpa` | 祖父 | 内环 | 隔代/完整家庭概率 |
| `gp-paternal-grandma` | 祖母 | 内环 | 同上 |
| `gp-maternal-grandpa` | 外公 | 内环 | 隔代/南方偏好概率 |
| `gp-maternal-grandma` | 外婆 | 内环 | 同上 |
| `sib-older-brother` | 哥哥 | 内环 | 双孩/多孩 |
| `sib-older-sister` | 姐姐 | 内环 | 双孩/多孩 |
| `sib-younger-brother` | 弟弟 | 内环 | 多孩 |
| `sib-younger-sister` | 妹妹 | 内环 | 多孩 |

- 结构↔槽合法组合表（单源本档）：独生 → 父+母（+祖辈 0–2 概率）；双孩 → 父/母 + 1 同辈（兄或姐）；多孩 → 父/母 + 2–3 同辈；单亲 → 单父 或 单母（+1 祖辈）；隔代 → 祖辈 2（祖父祖母 或 外公外婆，按南北派生）+ 父母中 0–1；
- 校验（validate 新区 `F`）：slot 唯一、结构↔槽组合合法、role 与 slot 一致、姓名非空；
- 图谱标签一律用 `role`（禁显示「父母/祖辈/同辈」泛称——那正是本次缺陷）。

## 二、偶遇层（encounter）

```jsonc
{ "id": "enc-024", "stage": "youth", "type": "encounter", "line": "fate",
  "ageMonths": 264, "text": "……", "detail": "……",
  "options": [ { "text": "……", "deltas3": {...}, "flag": "…" }, { "text": "就这样走过去" } ] }
```

- 不占主线/支线进度（不推进 line 值）；\|Δ3\| ≤1，无 resourceDeltas 或 \|Δ\| ≤3；
- **注入**：每阶段 0–3 条，由种子决定条数与抽选；可为 0（留白）；
- 文案 40–80 字；选项 2 个，或单选项「就这样走过去」（合法：跳过也是一种选择）；
- 首批库 ≥40 条（每阶段 ≥5）；validate 密度门新项。

## 三、节奏变体（`src/engine/rhythm.ts`）

| variant | 呈现 | 适用 | 口径 |
|---|---|---|---|
| `choice` | 正文 + 2–3 选项 | 主线/支线关键 | 沿现行 |
| `draw` | 三张背面卡，翻一张定结果 | 偶遇/运气节点（抽签/抓阄/摇号） | 牌面由种子派生；翻卡前后无信息差（公平）；三卡结果分布单源本档（本档定为等概率 1/3） |
| `odds` | 显示成功率 + 一次判定 | 有风险抉择（考试/表白/创业） | 成功率 = f(相关三观值, 资源) 单源公式；判定走种子 RNG；成/败各有 aftermath 文案 |
| `read` | 仅「继续」 | 时代卡、过场、他人故事 | 无选项 |
| `quick` | 两个 ≤6 字短词按钮 | 高频日常 | 选项文案 ≤6 字 |

- **分配规则**（单源）：`critical` → `draw` 或 `odds`（按事件 `risk` 字段，无 risk 默认 draw）；`encounter` → `draw` 或 `quick`；时代卡（era）→ `read`；`main`/`context` 常规 → `choice`，其中 `quick` 池单独标注；
- **节奏门**：每阶段实际出现的变体种类 ≥3；单阶段同变体连续 ≤3 次（防单调）；
- 概率可复现：同种子 + 同选择序列 → 同判定结果（单测断言）。

## 四、文本长度口径（治选择疲劳，量化门）

| 项 | 门限 |
|---|---|
| 正文 `text`（主句） | 中位 ≤120 字；P90 ≤150 字；单条 ≤180 字 |
| `detail`（细看层） | 不限（v4 原文迁入）但单条 ≤600 字 |
| 选项 `options[].text` | 中位 ≤10 字；≥20 字占比 ≤10%；单条 ≤16 字 |
| 每题选项数 | 2–3（关键节点 3，日常 2；`quick` 变体固定 2） |
| **单屏可见总量** | 正文 + 全部选项 ≤160 字（E2E 计算） |

- 实现纪律：**内容零损失**——v4 写实化原文整段迁入 `detail`，不得删改后再迁；`detail` 覆盖 100%（validate 校验非空）；
- 校验：`validate:story` 增 `S.LEN2`（主句）、`S.OPT`（选项）、`S.DETAIL`（覆盖）三项；变异自检各一。

## 五、开局四步（信息架构）

| 步 | 内容 | 出口条件 |
|---|---|---|
| 1 选玩法 | 随机出生 / 手选四要素 / 自定义八因素（三张大按钮，其余隐藏） | 选一个 |
| 2 填要素 | 对应表单（手选四要素 或 自定义八因素） | 必填齐 |
| 3 出生证明 | 一张「出生证明」样式卡：出生年 / 南北 / 城乡 / 家庭结构 / 父母职业 / 家境 / 家庭成员逐位姓名 / 种子码 | 「用这个」或「再来一次」（随机态可用） |
| 4 入场 | 一句开场白 + 开始按钮 | 点开始 |

- 进度指示 1/4–4/4；任何一步可回退上一步（不丢已填值）；
- 出生证明八因素**全部显性展示**（治「随机看不到结果」）。

### §二 ▸ 增补：偶遇层落地细节

- **落位**：40 条进 `src/data/events.json`（`type: "encounter"`，id 沿用 `{stage}-9xx` 段，与主线卡同库）；
- **不占池**：`pickEvent` 候选池显式排除 `encounter`（否则偶遇会被当成普通支线卡排进主线）；注入走 `encounterFor(state)`；
- **配额**：每阶段 0–3 由 `seededDraw(seed, 900 + stageIndex×13)` 四等分派生；实测 8 局 × 8 阶段的配额串（`1000: 01123221` / `1001: 02302130` …）里 0 条阶段真实存在——留白是口径的一部分；
- **月龄单调**：只允许 `floor ≤ 偶遇月龄 ≤ 下一张主线卡月龄` 且本阶段已出过 ≥1 张真卡（否则偶遇会插在开场之前，把 `pickEvent` 的 floor 抬到 22 个月、直接吃掉 3 个月的开场卡——E2E 年份单调断言抓出）；
- **不连发 / 不贴 critical**：上一张是偶遇或 critical 时不插；
- **variant 只用 draw/quick**：原表 §三「encounter → draw 或 quick」为准；本棒初稿把 13 条写成 `read`（违规），已改为 `draw`（门禁：`variant` 字段只认 `draw|quick`）；
- **图标**：40 条已在 `icon-map.json` 补齐（语义复用既有 250 枚 SVG，豁免数不变）。

### §三 ▸ 增补：quick 阈值与「同变体连续 ≤3」的判据面（**实测修正**）

原表写 quick = 「两个 ≤6 字短词按钮」。瘦身后按 ≤6 字筛，**每阶段只剩 0–2 张卡可用**（实测 infant 0/30、teen 1/30 …），于是 `choice` 会连片出现：40 局模拟里最长连片 **28 张**——即「防单调」的门自己制造单调。本棒按实测把阈值定到**可达的最小档**：

| quick 选项字数上限 | 每阶段可用卡 | 40 局最长 choice 连片 |
|---|---|---|
| ≤6（原表） | 0–2 / 30 | 28（不可达） |
| ≤10 | 12–20 / 30 | 6 |
| ≤12 | — | 4 |
| **≤13（定档）** | **10–20 / 30** | **3（达标）** |
| ≤16 | 全部 | 0（无区分度） |

同时明确两点：

1. **quick 是呈现层**：只换操作层密集度（紧凑 2–3 按钮），选项文案与判定一字不改；因此对任何 2–3 选项卡都成立，不需要改文案去凑阈值（本棒曾试把选项删到 2 个，因会改动判定输入而放弃）；
2. **「同变体连续 ≤3」只判非 critical 段**：v3 调度口径（[v3/02 §一](../../v3/02-数据与口径.md)，K11 冻结）把 critical 全部排在阶段末尾、按月龄递增，teen 阶段 4 张 critical 结构上必然连发 4 张。若为凑门的数字把某张 critical 的 `odds` 改成 `draw`，会改掉「显示成功率 + 一次种子判定」的呈现语义——那是拿口径迁就门。故门只判**玩家日常抽卡节奏**（非 critical 段），critical 段单独记录实测值供人工目检（`check-rhythm.mjs` 输出里 `critical 段 N`）。

### §四 ▸ 增补：v4 四项写实门的判据面（扫原文）

`S.LEN`/`S.ERA`/`S.SENSE`/`S.REF` 四项改扫 **`detail ?? text`（完整原文）**：瘦身后主句是原文前缀，写实化资产整段在 `detail`，门随内容走而不是随字段走（内容零损失的可验证形式）。展示面另由 `S.LEN2`/`S.OPT`/`S.DETAIL` 三项守（主句中位 ≤120 / 选项中位 ≤10 且单条 ≤16 / detail 覆盖 100% 且以主句开头）。

### §四 ▸ 增补：选项折叠层

选项短句化后，短句化前的原选项文案进 `options[].detail`（可选字段）。`detail` 与 `text` 相同的选项不得留空壳（`S.DETAIL` 守门）；UI 以 `title="原话：…"` 呈现（M1 最小接线，M2 可改为展开层）。
