## 一、必须承认的方向纠偏

**v4「文本写实化」用力过猛**：当时的口径是「critical ≥180 字 / context ≥100 字、五感 ≥2 处、互引 ≥1 处」，结果是正文中位 207 字。对**阅读型人生模拟**这是合理的；但对**游戏**这是灾难——玩家一屏要读 270 字再决定。5.0 的核心矛盾处理：

- **短句正文 + 可选深度**：正文控在 80–120 字（关键转折可到 150），把 v4 写好的细节**移入可展开的「细看」层**（点开读全，不点不影响决策）；
- **这是"文本写实"与"游戏节奏"的调和，不是退回 v3 的粗糙**——内容不删，只是折叠。

## 二、5.0 定位宣言（草案）

「《心路》5.0——一屏一句话，一个决定。你可以读得深，也可以走得快；偶遇会自己找上门，有些路口要看运气，有些门要你自己找钥匙。」

## 三、机制层

### 3.1 家庭槽位逐位命名（缺陷修复，最高优先）
- `npcs.json` 重构：每槽 `{ id, role, name, slot }`——`role` 细分（父亲/母亲/祖父/祖母/外公/外婆/兄/姐/弟/妹），`slot` 唯一（parent-father 等）；
- 家庭生成器按结构选槽：双孩 → 父+母+1 同辈；隔代 → 父+母+祖父+祖母（或外公外婆，南北/地域派生）；单亲 → 单父或单母；
- 图谱标签直接用 `role`（不再显示「父母」泛称）；
- 校验：槽位唯一性 + 结构↔槽组合合法（validate 新区）。

### 3.2 事件层次显性化 + 偶遇层
- 现有 `context`（183 条）在 UI 明确标为「日常/偶遇」并用不同视觉重量（非边框，用留白与字号）；
- 新增 `encounter` 类型（**偶遇层**）：不占主线/支线进度，随机触发、低概率、无三观大偏移（\|Δ3\|≤1），作用 = **氛围与人味**（街头卖艺、旧友重逢、路边一只猫）；
- 注入：每阶段 0–3 条（种子决定），可为 0——**有留白才显得偶遇珍贵**；
- 密度口径：首批 ≥40 条（每阶段 ≥5），文案 40–80 字、选项 2 个或「就这样走过去」（单选项也算一种玩法）。

### 3.3 节奏变体（治「一直是同一种选择页」）
五种呈现，按事件类型自动分配：

| 变体 | 呈现 | 用在哪 |
|---|---|---|
| **抉择卡** | 正文+选项（现有） | 主线/支线关键点 |
| **抽卡**（概率） | 三张背面卡，翻开一张定结果（种子决定牌面） | 偶遇、运气节点（抽签/抓阄/摇号） |
| **掷骰/概率条** | 显示「七成希望」+ 一次判定（成败都有文案） | 有风险的抉择（考试、表白、创业） |
| **静读** | 只有「继续」，无选项 | 时代卡、叙事过场、别人的故事 |
| **小抉择二选一** | 两个短词按钮（≤6 字） | 高频日常，降低选择成本 |

- 口径：每阶段至少出现 3 种变体（节奏门）；概率判定复用种子化 RNG（可复现契约不变）。

### 3.4 文本瘦身（治选择疲劳，量化门）
| 指标 | 现状 | 5.0 目标 |
|---|---|---|
| 正文中位 | 207 字 | **≤120 字** |
| 正文 P90 | 247 字 | ≤150 字 |
| 选项中位 | 20 字 | **≤10 字** |
| ≥20 字选项占比 | 52.5% | **≤10%** |
| 每题选项数 | 固定 3 | 2–3（关键节点 3，日常 2） |
| 单屏总阅读量 | ≈270 字 | **≤160 字** |

- 实现：正文**主句 ≤120 字 + 可选「细看」层**（原文 v4 版本进 detail 字段，点开才展开）；选项改为**动宾短句**（「接过钥匙」而非「接下驻外，把家里的钥匙托付给邻居」）；
- 门禁：`validate:story` 增加长度门（主句/选项两档），变异自检必红。

### 3.5 解密类玩法（D10，待拍板）
- **轻量线索玩法**：少数关键节点（每阶段 ≤1）给 2–3 条线索（信件/旧物/他人一句话），玩家选「你怎么理解」→ 影响 flag 与后续事件解锁；
- **不做**：真·解谜关卡（拼图/找物/密码锁）——与人生模拟主体不符，成本高；
- 推荐：**A 轻量线索（每阶段 ≤1 处）**；B 不做（保持纯选择）；C 强解谜（不推荐）。

## 四、呈现层

### 4.1 开局屏分层（治「元素杂乱」）
一屏一个问题，四步递进（进度指示 1/4）：
1. **选玩法**：随机出生 / 手选 / 自定义（三张大按钮，其余全隐藏）
2. **（若手选/自定义）** 要素填写
3. **确认出生**：一张「出生证明」样式的卡——年份、地域、家庭结构、父母职业、家境、家庭成员姓名（一屏读完，这就是「随机到的是什么」）
4. **入场**：一句开场 + 开始

### 4.2 随机结果可读化（治 #3）
- 随机后**先出「出生证明」卡**再入场（含八因素逐条 + 家庭成员 + 「再来一次」/「用这个」）；
- 种子码在此屏展示（可复制），不在游戏内打扰。

### 4.3 主题重做（治 #4，D8 待拍板）
现有四款被否（「背景好丑」），重新设计方向：

| 方案 | 说明 |
|---|---|
| **A 素纸**（推荐） | 米白纸底 + 极细纸纹（几乎不可见）+ 单一墨色 + 一个强调色；无图案、无装饰，靠排印与留白撑质感 |
| B 昼夜四时 | 晨/昼/暮/夜四款按时间自动切换（可手选），色调随真实时间变化 |
| C 极简黑白 | 纯白/纯黑两档，像电子书阅读器 |

- 独立子决策：**背景是否需要纹理**（当前纸纹你觉得丑，可能就删掉纹理走纯色）；
- D8 推荐 A + 无纹理。

### 4.4 图谱重做（治 #6）
- **双视图**：
  - **家谱树**（默认）：父母在上、同辈并列、伴侣与子女在下——像真正的家谱，一眼看懂血缘；
  - **关系网**：环形（现有），但治疗视觉——节点用头像圆 + 姓名标签，连线用曲线（不用折线），亲疏用连线粗细 + 透明度，标签避让；
- 信息：每个节点可点开看「关系值 + 变化记录（什么时候变的、因为什么）」——关系不再是一个数字。

### 4.5 卡片阅读优先重构（治 #9）
- **三层**：正文（视觉焦点，最大字号、最宽留白）→ 选项（次之）→ 辅助信息（年份/线别/状态，弱化为一行小字，可折叠）；
- 状态条从常驻改为**顶部一条细线 + 悬停/点击展开**（不抢注意力但随时可查）；
- 图标缩小、置于正文旁（不占独立行）。

## 五、配图升级（治 #5，D9 待拍板）

**现状**：243 枚 Game-Icons 是**单色小图标**（16–24px），不是「配图」。**问题本质：玩家要的是「配图」，我们给的是「图标」。**

| 方案 | 内容 | 成本 | 许可 |
|---|---|---|---|
| **A 语义图库**（推荐） | 建 40–60 张**具象插画**（CC0/公版：老照片、年代物件照、场景画），按语义标签（厨房/教室/车站/工厂/医院/婚礼/葬礼…）挂到事件；一图可复用于同类事件 | 中（检索+整理+压缩） | CC0/公版优先，CC-BY 署名 |
| B 每事件一图 | 243 张不重复 | 高（选题+采集+预算门必爆） | 同上 |
| C 保持图标 | 现状 | 零 | — |

- A 的配图规则：**事件配图 = 语义标签 → 图库**；卡片上配图**占据上半屏**（不再是小图标），真正成为「这张卡在说什么」的视觉答案；
- 预算：配图进 dist 前统一压缩 WebP（≤40KB/张），预算门重审（850→待实测）；
- 素材纪律沿 v4：CC0 优先、逐张对文案留痕、许可门白名单扩展、不虚构不误导。
