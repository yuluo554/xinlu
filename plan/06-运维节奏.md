# 06 · 运维节奏（发布后）

> 承接 `ai-tool-ops-cadence` 方法论，按游戏项目改写。核心总原则不变：**维护的动力必须换成可度量的缺口，不靠热情；没有事件、没有缺口时，正确的动作是不动。** 迭代队列唯一存放 `plan/backlog.md`（M4 内容完成后启用）。

## 八类缺口（游戏版轮转清单，每周 30 分钟查一类）

| # | 类型 | 游戏语境下的查法 | 证据形态 |
|---|---|---|---|
| 1 | 内容缺口 | 阶段事件密度复跑 `npm run validate`；文案重复度抽查 | validate 输出 |
| 2 | 平衡缺口 | 某 MBTI 路线/结局不可达或过易（换种子批跑 + 实玩） | 批跑统计 + 通关留痕 |
| 3 | 文档数字漂移 | README/00 台账的事件数、结局数 vs `npm run validate --count` 对账 | 两侧数字对照 |
| 4 | 可复现性 | 同 seed 复跑全等断言仍绿 | vitest 输出 |
| 5 | 输入鲁棒性 | 损坏存档 / 极端选项序列 / 清空 localStorage 中途 | 复现步骤 + 截图 |
| 6 | dogfooding | 轮玩全结局，记录体验断点 | 通关记录 |
| 7 | 性能基线 | 首屏可交互时间、雷达图重绘帧率（对比 M5 基线） | 记录值 |
| 8 | 跨端漂移 | 375px 与 1280px 表现分叉（断行/溢出/触控目标） | 截图对照 |

## 节奏

- **周自查**：每周固定 30 分钟，八类轮转一类，发现写入 backlog（**必须带可复现证据：命令 + 输出**，「我觉得」不入队）；
- **月迭代**：≤2 项，得分 = 影响分(1–3) × 覆盖面(1–3) ÷ 成本系数(0.5/1/2)，≥4 本月做；**完成定义含防回退测试**（把改动回滚，测试必须变红）；
- **内容版本规则**（双层版本的游戏版）：结局/画像判定结论变化 → 主版本 +1，Release 注明「历史存档结论可能变化，需重开」；新增事件/结局 → 次版本 +1；纯文案微调 → 补丁；只改错别字 → 不发版；
- **事件响应**：玩家报「判定反直觉/文案错误」按最高优先级处理（判定可信 > 一切）。

## 归档判据（若未来停止维护）

满足任意 2 条可归档：无外部 issue/star；与后续项目高度同构；目标已达成且无长期玩家。**有任一外部反馈即保留**。操作顺序：先推齐提交 → README 顶部加归档说明 → push → `gh repo archive`（可逆，用归档不用删除）。Pages 下线与否在归档说明中明示。

## 反模式（明确禁止）

为活跃度空提交；无限重构；加事件不加校验；只看测试数量不看防回退有效性；一次开 >2 个迭代项；把 backlog 当愿望清单（无证据不入队）；用 star 当进度指标。
